# Limitations and appropriate use

- **Not Google's engine.** The parser and executor implement a documented subset of YARA-L 2.0 Search. Valid Google syntax outside the subset is reported as "not run here", separately from mistakes. Passing here does not prove a query compiles in a tenant.
- **Flat events.** Real UDM has repeated fields (`security_result`, `principal.ip`, `network.dns.questions`, `network.email.to`). This dataset carries one value per field, so `any`, index syntax and negation-over-repeated-fields behave more simply here than in production.
- **Documentation conflict.** Google's "Use conditions in search and dashboards" page documents outcome `condition:` in Search; two other pages say Search does not use `condition`. Chapter 6 teaches the documented form and tells learners to verify in their tenant. No tenant run has been done.
- **Engine v2 follows the documentation as read on 2026-10-18 through search summaries**, because Google's pages could not be fetched from the build container. Specifically: `dedup` is accepted between `condition` and `order` and keeps the first row per distinct key after ordering; on an aggregated query only match keys and outcome names may be dedup keys. `array` and `array_distinct` are cut at 1,000 elements (Search's limit; rules and dashboards differ). `earliest`/`latest` take the event timestamp. The time functions accept `"UTC"` (and `"GMT"`, Google's default) and report every other zone as *not run here*, because the dataset is read and rendered in UTC. Google caps list tests at ten per query; so does the trainer. Verify each shape in a tenant before relying on it.
- **Reference lists are bundled, not created.** In a tenant they are objects under Detection > Lists with their own permissions and limits; here they are content in `content/lists.json`. Data tables are not implemented.
- **Time buckets** use fixed clock-aligned windows (`by 5m`). Search's actual bucket alignment and the Search UI's time picker still govern real results.
- **Statistics limits** (90-day lookback, 100,000-row cap, ingestion lag) exist in Google Search and not here.
- **Scoring is formative.** Hints are free, the last hint is a full answer, and progress is editable local state. Nothing here is a credential or evidence of skill for an employer.
- **The Casebook check is structural, not a judgement of quality.** "Check my Casebook" verifies that an entry of the asked kind has its required fields, `HH:MM` UTC times, record IDs that exist in the dataset, references that resolve to an Evidence entry, support for a supported hypothesis, evidence behind a remediation item, no claim words without a record, and the anchors the mission names (an IP, a time, a record ID). A well-formed entry that reasons badly passes; a sharp insight with a missing field does not. It never compares your text with a model answer. The brief on the last mission puts your casebook beside the authored one for self-comparison and grades nothing.
- **The casebook shortcut depends on the keyboard layout.** `Alt`+`Shift`+`C` reaches the page in Chromium and Firefox and is matched on the physical key, but on Windows `Alt`+`Shift` alone can switch input languages and on some layouts the combination types a character first. The Casebook button in the top bar is always the fallback.
- **Notes are yours and only yours.** The Casebook is session-only unless remembered, bounded at 96 KB, exported only as a local Markdown file you start, and never uploaded. Nobody reviews it.
- **No real data, by design.** The dataset is generated by `tools/gen-data.mjs` with a fixed seed. If you want to practise against real logs, use the tools your employer authorizes and never paste real values here.
- **Accessibility is verified structurally, not with assistive technology.** Playwright tests assert accessible names, focus order, heading levels, live regions, the skip link, 320 px reflow and reduced motion, and a unit test asserts WCAG AA contrast for every colour token on every surface (see `docs/EVALUATION.md`). No session has been run with NVDA, JAWS or VoiceOver, and browser zoom at 200% is covered only by the 320 px reflow equivalent.
- **Browser tests run in one engine.** Seventeen Playwright tests drive the built `dist/` in Chromium; there is no Firefox or WebKit run, and the recorded runs used Node 22 with an existing Chromium build rather than the Playwright-managed one.
- **Learning effectiveness is unmeasured.** The course has been played end to end by its builders through the grader and the browser, and the friction log in `docs/EVALUATION.md` records what changed as a result. No learner outside the project has used it.
