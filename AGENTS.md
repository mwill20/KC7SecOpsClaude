# Instructions for coding assistants

Read `README.md`, `SECURITY.md` and `docs/threat-models/THREAT_MODEL.md` before changing anything.

- Browser-only, no runtime dependencies, no network calls, no accounts, no SIEM integration. Keep `connect-src 'none'`.
- Render with text nodes only. No `innerHTML`, `eval`, `new Function` or dynamic imports from user values.
- Grading is by execution against the fictional dataset through `site/engine/`. Do not replace it with string matching or AI grading.
- Content lives in `content/`; the dataset is generated by `tools/gen-data.mjs`. If you change either, run `npm run verify`: the content validator must prove every authored answer against the data and every build starter must fail until completed.
- Keep the dataset fictional: `.example` domains and documentation IP ranges only (enforced by `tests/unit/content.test.mjs`).
- Do not copy KC7Cyber content, scenarios, datasets or assets. Borrow teaching patterns, not material.
- Report unsupported Google syntax as `unsupported`, broken syntax as `invalid`, and wrong evidence as `incorrect`; never blur these.
- Every change to the engine or grader needs a should-fail test.
- No commit, push, publishing or license choice without the owner's instruction.
